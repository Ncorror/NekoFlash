# Capability Matrix

This file records capability/evidence direction, not current implementation status. Current implementation status lives only in `03_ROADMAP.md`. The detailed cross-archive gap analysis lives in `06_FULL_PROTOCOL_AUDIT.md`.

| Area | Evidence carried forward / audited gap | Rewrite direction |
|---|---|---|
| Professional capability policy | Previous clean-tree Product Charter + protocol/safety invariants; reaffirmed by owner and full audit | No Novice/Expert permission system, hidden capability tier, product allowlist/denylist or invented host authorization. Hard invariant / Device authority / Advisory / User intent are the only decision classes; see ADR 0005 |
| Target/session identity | A2/current tests and hardware observations | Separate `TargetId`, `SessionGeneration`, `TargetMode` and transport ownership |
| Diagnostics | A2/current source/tests + Phase 2 hardware runs | Structured evidence first; per-target session IDs + owner labels; fresh pre-export USB snapshot; deterministic multi-file ZIP plus text fallback; manifest and explicit sections only; redact secret protocol material in shareable bundles |
| Android USB lifecycle | Legacy/A2 descriptors, permission, attach/re-enumeration behavior + Phase 2 owner hardware PASS | Discovery/permission/open/claim are proven; ordinary ADB entry is auto-first. Before broad services, restore generation/process-aware permission callback identity, stale-callback rejection and detach/re-enumeration race coverage |
| ADB handshake | Legacy/A2 authentication knowledge + current POCO X3 Pro hardware PASS | Bounded `CNXN/AUTH` foundation with persistent RSA identity; auto-first entry advances one unambiguous canonical ADB target; manual controls remain diagnostic fallback |
| ADB USB wire termination | Current AOSP requires host-to-device ZLP termination when a USB transfer ends exactly on endpoint `wMaxPacketSize`; no archive has an explicit/verified ADB ZLP contract | Before broad `WRTE`/Sync traffic, make endpoint-aware Zero-Length Packet behavior an executable transport invariant and hardware-test boundary-sized writes. Backend mechanism is implementation detail; proven wire behavior is mandatory |
| ADB stream/service core | Legacy broad services; previous `main` one-reader concurrent stream router, mailboxes and generic `AdbServiceCall` | Restore one physical reader + logical stream routing and a generic raw service/open path. Typed clients add parsing/UX, never permission or a service allowlist |
| ADB shell/install/reboot/forward/reverse | Legacy breadth + previous `main` implementations/tests | Rebuild over the shared stream/service engine, including shell v2/legacy, interactive shell, normal/streaming install, install-multiple, reboot and forward/reverse |
| ADB modern install workflows | No archive implements Incremental Server + V4/`.idsig` incremental install or first-class atomic `install-multi-package` | Add these as professional host workflows over the shared stream/service/file engine after baseline install is correct; do not confuse generic shell reachability with a completed host-side file/session implementation |
| ADB Sync | Previous `main` had `STAT`/`RECV`/`SEND`; docs promised `LIST` but production code did not implement it. No archive has modern Sync v2/compression | Restore v1 with the missing `LIST` path, then add modern stat/list/send/recv v2 and Brotli/LZ4/Zstd negotiation where peer features support it |
| ADB Burst Mode | No archive implements current AOSP delayed-ACK/Burst Mode negotiation | Optional throughput work after baseline streams are correct: negotiate available send bytes through `A_OPEN`/`A_OKAY`, keep fallback interoperable, and benchmark on NekoFlash hardware rather than promising AOSP lab numbers |
| Wireless ADB | No archive implements modern pairing/TLS/mDNS host transport; Legacy `tcpip:<port>` only asks a USB-connected adbd to enter legacy TCP mode | Add host-side pairing-code/QR-compatible pairing foundation, TLS ADB transport, mDNS discovery and paired-device connection as new work; do not confuse it with legacy `adb tcpip` |
| Specialized/long-lived ADB services | AOSP exposes services such as `jdwp:<pid>`, `track-jdwp`, `track-app:` and framebuffer; previous `main` generic service path is the architectural escape hatch | Keep a professional raw service surface. Add typed/streaming helpers only where useful; long-lived services use streaming semantics rather than a finite-response collector |
| Fastboot command/transaction core | Legacy broad raw command behavior; A2 transaction tests; previous `main` single-lane protocol/mutation model | Future single transaction lane; raw command surface first; preserve peer `INFO/TEXT/OKAY/FAIL`, exact byte accounting, role evidence and `Unknown` mutation semantics; no command-name capability allowlist |
| Fastboot DATA backends | Legacy ~42 MB/s Native USBFS hardware flashes; A2 128 MiB / ~4.437 s Java `UsbRequest` baseline; A2 ownership/cancel tests | Preselect `ASYNC_USB_REQUEST` + required `NATIVE_USBFS` + bounded `SYNC_BULK` before DATA. No backend switch/retry after negotiation; Native USBFS needs fresh hardware validation. DATA IN/fetch measured separately |
| Fastboot staging/network transport | No archive contains first-class AOSP `stage`/`get_staged` host flows or Fastboot `tcp:`/`udp:` transport | Lower-priority professional backlog: stage/get_staged reuse DATA OUT/IN; any network transport shares the same Fastboot protocol/transaction engine rather than forking command policy |
| Fastboot logical/fastbootd workflows | Legacy command breadth + previous `main` role/logical helpers | Restore bootloader/fastbootd role-aware getvar/partition/logical/GSI/snapshot/update-super workflows over the shared engine; distinguish raw wire commands from multi-step host orchestration |
| Fastboot factory `update` / `flashall` | **Missing across archives**; Legacy explicitly declined to emulate desktop-fastboot batch logic | New first-class factory-image/task orchestration, including file/package parsing, mode transitions, `fastboot-info.txt`/equivalent task semantics and honest postconditions |
| Fastboot sparse images | **Incomplete across archives**; previous `main` parser/planner was not wired into production flash and could not re-split already-sparse input | Complete end-to-end sparse flashing under `max-download-size`, including already-sparse re-splitting and mutation-aware chunk sequencing |
| Recovery/Sideload | Legacy behavior; A2 transfer/mutation/correlation tests; previous `main` session/evidence work | Distinguish transfer completion from installation success; retain unique-vs-served progress, generation/quarantine semantics and `Unknown` after ambiguous mutation |
| Quick Flash | Legacy behavior/evidence | Future guided use case over the same Fastboot engine; warnings/confirmations express user intent, never a private capability policy |
| Mi Unlock | Legacy source/historical evidence | Future vendor use case over generic Fastboot core with fresh final verification; no separate hidden authorization layer |
| Brand | Legacy exact assets/colors | Welcome immutable; launcher reference retained; semantic Legacy color DNA |
